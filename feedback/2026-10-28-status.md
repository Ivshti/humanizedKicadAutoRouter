## Nano bar-display board (2026-10-26-nano-bar39-why-it-could-not-route.md)

| # | asked | done |
|---|---|---|
| 1 | vias under module bodies | Only an antenna bans vias under its body; under a module or connector a via goes wherever its pads leave room. Tracks of other nets still stay off a body on its own side. |
| 2 | power on In2 | A `.kicad_dru` "disallow track" rule that names the nets allowed on a plane layer opens it to them. They run trunks there and drop by via at a signal via's price. Pour pieces their tracks cut loose get stitched. |
| 3 | zero-current power tap priced as power | Such a tap gets a signal via's size and price; its width stays the class width. |
| 4 | reconnect trades nets, names the wrong ones | Negotiation and reconnect run as transactions: if they end no better than they began, everything goes back. Open connections are named again after tidying, from the final state. |
| 5 | tidy edits other nets and the designer's copper | Under `--nets` tidy edits only those nets; under `--keep-copper` never the designer's copper. Return vias go only beside this run's vias, and there is no open-pour stitching grid under `--keep-copper`. |
| 6 | stranded GND pad not reported | Judged from the final DRC. A route of this run that walls a GND pad's piece of pour off from every via is laid again round it, kept only if all it held is joined again; otherwise the log says so. |
| 7 | say when an antenna boxes a net in | A placement note names connections whose straight line crosses an antenna and that are unrouted or run more than 1.8x that line. On `case-final-opens`: LED_DIN 3.3x, CHG_CE 2.6x (10 vias), CHG_STAT 2.6x. |
| 8 | crossing forced by pin order | Not done. |
| 9 | the way round the patch | Partly: the via ban under J_CTP (cause 1) is gone. Costing the path round an antenna's edge is not done. |

On `case-final-opens`, every connection now routes (run A left SYS and CHG_CE apart and
traded LED_DIN and CHG_STAT away). Of the 6 opens, 4 are closed. The 2 left:
- the owner's own unfinished V3V3 stub at U6, which shorts two unconnected pins (it is
  in the input);
- U10's GND pin 2. The log names it: "has its pour walled off by copper this run did
  not lay". The wall is the hand-routed IMU_INT1 track west of the pin column; no route
  of this run is on the piece's edge.

## Touching copper (2026-10-26-nano-touching-copper.md)

The board's own copper is joined wherever shapes overlap by more than 2 µm, as KiCad
joins it; copper that only touches is not. On the repro: 37 connections recognised as
made (28 before), none of the four links routed again, DRC 0 / 0. Stitching is scoped
as in item 5 above.

## Ambire signer reports

- BAT_N neck: current never falls back to landing on a tap; it lands on its own end pad.
  `flowcheck` checks every planned current path after tidy.
- Reroutes (1), pour walled off: see item 6 above.
- `viaPadGapMm` (0.2 mm, from that board's owner) no longer applies inside a ball grid's
  courtyard, where a via between balls is how a BGA is fanned out. On the FPGA card it
  halved what pass 1 could route.

## Also fixed while gating

- A track ending on another's centreline that KiCad leaves dangling: only that host
  track is split (the open item from `multilayer`).
- The corner pass could cut the same corner for ever; a cut must now shorten the route.
